# QFOME Backend

API REST do QFOME construida com Java 21 e Spring Boot 3.5.

## Stack

- Java 21
- Spring Boot 3.5 (Web, Data JPA, Validation, Actuator)
- SQLite (banco em arquivo local, via `sqlite-jdbc` + dialeto `hibernate-community-dialects`)
- Lombok

## Como rodar

```bash
# Windows
.\mvnw.cmd spring-boot:run

# Linux/macOS
./mvnw spring-boot:run
```

API disponivel em `http://localhost:8080`. Nao precisa instalar banco: o arquivo
`data/qfome.db` e criado no primeiro start, com o schema e o seed.

## Banco de dados (SQLite)

- Arquivo: `data/qfome.db` (relativo a pasta onde o backend roda; ignorado pelo git).
- Schema: `src/main/resources/db/schema.sql`, o **Anexo A** adaptado para SQLite:
  `BIGINT GENERATED BY DEFAULT AS IDENTITY` virou `INTEGER PRIMARY KEY AUTOINCREMENT`
  e cada tabela ganhou `IF NOT EXISTS`. Tabelas: `usuario`, `categoria`, `produto`,
  `adicional`, `carrinho`, `item_carrinho`, `item_carrinho_adicional`, `pedido`,
  `item_pedido`, `item_pedido_adicional`.
- Seed: `src/main/resources/db/data.sql` (6 categorias, 29 produtos, 87 adicionais).
  Usa ids fixos + `ON CONFLICT DO NOTHING`, entao roda a cada start sem duplicar.
- O Hibernate so mapeia as tabelas (`ddl-auto: none`); quem cria o schema e o script.
- Chaves estrangeiras ligadas na URL (`foreign_keys=on`): apagar um produto que ja esta
  em pedido responde `409`.
- Para inspecionar ou editar: abra `data/qfome.db` no [DB Browser for SQLite](https://sqlitebrowser.org/).
- Para zerar o banco: pare o backend e apague `data/qfome.db`.

## Endpoints

### Health

```
GET /actuator/health
```

### Autenticacao

```
POST /auth/register   { name, email, password }
POST /auth/login      { email, password }
-> { id, name, email, perfil, message }
```

### Categorias

```
GET    /categorias
GET    /categorias/{id}
POST   /categorias        { nome }
PUT    /categorias/{id}   { nome }
DELETE /categorias/{id}
```

### Produtos

```
GET    /produtos               ?categoria={id} (opcional)
GET    /produtos/{id}
POST   /produtos               { categoriaId, nome, descricao, preco, imagemUrl, tempoPreparoMin }
PUT    /produtos/{id}
DELETE /produtos/{id}
```

Cada produto volta com a lista de `adicionais` (`{ id, nome, preco }`).

### Carrinho

```
GET    /carrinho/{usuarioId}
POST   /carrinho/{usuarioId}/itens            { produtoId, quantidade, observacao, adicionais: [ids] }
PATCH  /carrinho/{usuarioId}/itens/{id}?quantidade=N
DELETE /carrinho/{usuarioId}/itens/{id}
DELETE /carrinho/{usuarioId}/limpar
```

### Checkout

```
POST /checkout
{
  "usuarioId": 1,
  "formaPagamento": "pix",            // pix | cartao | dinheiro
  "endereco": { "cep": "01310-100", "logradouro": "...", "numero": "...", "bairro": "...", "cidade": "..." },
  "itens": [ { "produtoId": 1, "quantidade": 2, "observacao": "sem cebola", "adicionais": [1, 2] } ]
}
```

Subtotal, taxa de entrega (R$ 6,90 abaixo de R$ 45) e total sao calculados no servidor
com os precos do banco. O preco do produto e de cada adicional fica congelado no pedido.

### Pedidos

```
GET /pedidos/cliente/{usuarioId}
GET /pedidos/acompanhar/{codigo}
```

Status: `RECEBIDO`, `EM_PREPARO`, `SAIU_PARA_ENTREGA`, `ENTREGUE`.

## Variaveis de ambiente

```env
SERVER_PORT=8080
SPRING_DATASOURCE_URL=jdbc:sqlite:./data/qfome.db?foreign_keys=on&busy_timeout=5000&date_class=TEXT
APP_CORS_ALLOWED_ORIGINS=http://localhost:3000,http://localhost:3001,http://localhost:8081
```

O app mobile nativo nao passa por CORS; a origem `8081` e para o Expo no navegador.

Arquivo completo: `src/main/resources/application.yml`

## Testes

```bash
./mvnw test        # Linux/macOS
.\mvnw.cmd test    # Windows
```

Os testes usam um SQLite separado em `target/qfome-test.db`. Cobrem `GET /actuator/health`
e o fluxo do app (`PedidoFluxoIntegrationTest`): catalogo do seed, cadastro/login,
checkout com adicionais e totais, taxa de entrega, adicional de outro produto (400),
historico, acompanhamento, carrinho e exclusao bloqueada por FK (409).

## Estrutura

```
src/main/java/com/qfome/
  config/        CorsConfig, GlobalExceptionHandler, QfomeSQLiteDialect
  controller/    AuthController, CategoriaController, ProdutoController, ClienteController,
                 CarrinhoController, CheckoutController, PedidoAcompanhamentoController
  model/         Usuario, Categoria, Produto, Adicional, Carrinho, ItemCarrinho,
                 Pedido, ItemPedido, ItemPedidoAdicional
  repository/    interfaces Spring Data JPA
  service/       logica de negocio
src/main/resources/
  application.yml
  db/schema.sql  Anexo A (SQLite)
  db/data.sql    seed de catalogo
```
